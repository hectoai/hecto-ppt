# 헥토 슬라이드

헥토 슬라이드는 **타이포 중심의 사내 리포트 톤**이다. 흰 캔버스, 회색 본문, 페이지당 오렌지 한 곳. 그래디언트도 사진도 장식 도형도 없다. 강해 보이는 이유는 꾸며서가 아니라 구조가 일정해서다.

## 시작 전에

**의존성은 네가 설치한다. 사용자에게 시키지 않는다.**

헬퍼를 처음 부르기 전에 확인하고, 없으면 그 자리에서 깐다.

```
npm install               # 스킬 폴더에서. 없으면 Cannot find module 'pptxgenjs'로 죽는다
pip install python-pptx   # verify_pptx.py용
```

Pretendard만 예외다. 시스템 폰트라 자동 설치가 안 된다. 없어도 생성은 되지만 PowerPoint가 다른 한글 폰트로 대체해 렌더가 달라지므로, `fonts/`의 OTF를 설치하라고 **한 번 안내하고 넘어간다.** 설치를 기다리느라 작업을 멈추지 않는다.

## 작업 순서

1. **콘텐츠를 먼저 확정한다.** 장별 제목, 각 슬라이드가 말할 한 문장, 근거. 이게 정해지기 전에 레이아웃을 고르지 않는다.
2. **슬라이드마다 레이아웃을 고른다.** 아래 선택 규칙을 쓴다. 습관이 아니라 콘텐츠의 모양에서 고른다.
3. **`lib/hecto.js` 헬퍼로 빌드한다.** 좌표를 직접 쓰지 않는다. 헬퍼가 스펙 상수를 갖고 있다.
4. **검증한다.** `python scripts/verify_pptx.py <출력.pptx>`. 통과하지 못하면 배포하지 않는다.
5. **눈으로 확인한다.** LibreOffice로 PDF 변환 후 이미지로 뽑아 본다. 검증은 좌표만 보고 문장은 안 본다.

## 레이아웃 선택

콘텐츠가 어떤 모양인지가 레이아웃을 정한다. 같은 레이아웃이 네 장 이어지면 템플릿처럼 읽힌다.

| 콘텐츠의 모양 | 레이아웃 |
|---|---|
| 자료의 첫 장 | `slide-cover` |
| 장 목록 | `slide-toc` |
| 장의 시작 | `slide-section-divider` |
| 나란한 두 주제 | `slide-content-standard` (페어드 섹션 블록 `01.` / `02.`) |
| 마주 보는 두 선택지·전후 대비 | `slide-comparison` (`A.` / `B.`) |
| 순서가 있는 3~5단계 | `slide-step-process` |
| 나란한 세 항목 | `slide-3col` |
| 나란한 네 항목 | `slide-2x2-grid` |
| 지표 3개 + 뒷받침 표 | `slide-kpi-row` |
| 기억시킬 숫자 하나 | `slide-hero-stat` |
| 마무리 요약 3~5개 | `slide-takeaways` |
| 자료의 마지막 장 | `slide-end` (필수) |

**판단이 갈릴 때**

- 항목들이 동등한가, 순서가 있는가? 동등하면 3단/2×2, 순서가 있으면 스텝 스트립.
- 숫자 하나가 지배하는가, 여러 개가 경쟁하는가? 하나면 히어로 스탯, 여럿이면 KPI 3연.
- 두 주제가 나란한가, 맞서는가? 나란하면 `01.`/`02.`, 맞서면 `A.`/`B.`.

## 절대 규칙

어기면 검증에서 걸린다. 걸리지 않더라도 어기지 않는다.

- **캔버스는 16:9, 13.333" × 7.500"만.** 4:3도 A4도 없다.
- **폰트는 Pretendard 하나.** 400과 700 두 굵기만 쓴다. 이탤릭 없음.
- **팔레트 14색 밖으로 나가지 않는다.** 새 색이 필요하면 그 슬라이드가 잘못된 것이다.
- **페이지당 시그니처 오렌지는 한 곳.** 셰브론 챕터 필은 크롬이라 세지 않는다.
- **모든 자료는 `slide-end`로 닫는다.** `E. O. D.` 한 줄.
- **커버의 컨피덴셜 문구는 verbatim.** 번역도 축약도 마침표 추가도 안 된다.
- **출처는 외부 기록이 있을 때만.** `자체 분석`은 쓰지 않는다.
- **차트·타임라인·풀 인용·콜아웃은 범위 밖.** 숫자는 데이터 표나 KPI 타일로 간다.
- **한국어 문서에 em dash를 쓰지 않는다.**

## 자주 나오는 실수

이 시스템에서 실제로 반복된 것들이다.

- **셰브론 헤더 좌표를 손으로 쓴다.** 4~8px 어긋남이 가장 흔한 결함이다. 헬퍼를 쓴다.
- **출처 캡션을 옮긴다.** 자리가 없으면 캡션을 내릴 게 아니라 콘텐츠를 줄인다. 헬퍼는 위치 인자를 받지 않는다.
- **스텝 카드를 아무거나 활성화한다.** active는 그 슬라이드가 특정 단계를 파고들 때만이다. 개요 슬라이드에서는 전부 기본 상태다.
- **데이터 표 강조 열의 배경을 오렌지로 칠한다.** 강조는 **글자색**으로만 준다.
- **워드마크를 아무 컨테이너에나 넣는다.** PNG는 (배경색 × 컨테이너) 조합당 하나다. 커버용을 헤더 크기에 넣으면 눌린다.

## 참고 자료

필요할 때만 읽는다. 처음부터 다 읽지 않는다.

| 파일 | 언제 읽나 |
|---|---|
| `references/tokens.md` | 색·타이포·여백·도형의 정확한 값이 필요할 때 |
| `references/components.md` | 컴포넌트 하나의 구조와 치수가 필요할 때 |
| `references/layouts.md` | 레이아웃의 정확한 좌표와 선택 조건이 필요할 때 |
| `references/conventions.md` | 렌더링 동작, 하지 말아야 할 것, 알려진 공백 |

## 번들

- `assets/` 워드마크 PNG 3종. 배경색과 컨테이너 크기에 맞는 것을 쓴다
  - `logo-orange-on-white.png` 커버
  - `logo-orange-on-white-sm.png` 종료 슬라이드
  - `logo-orange-on-gray.png` 셰브론 헤더
- `fonts/` Pretendard Regular · Bold OTF. 시스템에 설치돼 있어야 PowerPoint와 LibreOffice가 제대로 렌더한다
- `lib/hecto.js` 좌표를 고정하는 헬퍼
- `scripts/verify_pptx.py` 규칙 11개 판정기
